# SF 탐사단 제품 방향 및 지속 개선 로드맵

> 이 문서는 SF 탐사단의 제품 원칙, Production 기준선, 기술적 경계, 개선 우선순위를 지속적으로 관리하는 기준 문서다. 기능을 추가하거나 IA·데이터 계약·공개 범위를 변경할 때 이 문서를 함께 갱신한다.

## 1. 제품 명제

SF 탐사단은 기능이 많은 SF 포털이 아니라 다음 순환을 돕는 **조용한 SF 관측소**다.

> SF를 발견한다 → 감상을 기록한다 → 다른 탐사자의 공개 신호와 연결된다 → 다시 새로운 SF를 발견한다.

Home은 모든 기능을 축소해 모아 놓는 메가 대시보드가 아니라 이 순환에 진입하는 가벼운 허브로 유지한다.

## 2. 제품 언어

- **탐사**: 작품·관측 정보·SF 개념을 둘러보는 상위 공간
- **발견**: 탐사 과정에서 사용자가 수행하는 행동
- **기록**: 개인 감상을 작성하고 보존하는 행동
- **신호**: 사용자가 명시적으로 공개한 기록
- **네트워크**: 공개 신호가 작품·개념·다른 기록과 연결되는 공간

상위 내비게이션은 `탐색 / 기록 / 네트워크 / 커뮤니티 / 내 정보`를 기준으로 유지한다. 동일 목적지에 탐색·발견·아카이브 등 서로 다른 이름을 혼용하지 않는다.

## 3. 보존할 핵심 원칙

### Home

- 단일 제품 흐름인 `발견 → 기록 → 연결`을 유지한다.
- 주 행동은 한 번에 하나가 명확해야 한다.
- Home에 전체 검색·작성 폼·지도·설정·프로필 기능을 다시 합치지 않는다.
- 전역 읽기 모드는 Home에서 렌더링하지 않는다.
- 섹션 순서는 `탐사 순환 → 오늘의 발견 → 새로 포착된 SF → 미디어 아카이브 → 최근 탐사 신호 → Contact`를 기준으로 한다.
- Home 미디어는 통합 피드의 최신 실제 자료를 최대 2개만 표시하고, embed·autoplay·carousel·중복 검색/분류 UI를 추가하지 않는다.
- Contact는 커뮤니티 참여와 협업 문의를 분리해 실제 `https`·`mailto` 링크로 제공하고, 큰 홍보 CTA보다 조용한 footer 접점을 우선한다.

### 데이터와 상태

- 레이더·통계·네트워크에는 실제 데이터만 사용한다.
- 가짜 신호, 랜덤 활동량, 데모 네트워크를 실제 활동처럼 표시하지 않는다.
- 정상 0건, 로딩, 설정 누락, 네트워크 오류, 부분 소스 장애를 구분한다.
- 부분 실패를 전체 성공이나 전체 갱신으로 표현하지 않는다.
- stale fallback을 사용하면 운영 상태에서도 명시적으로 구분한다.

### 기록과 공개

- 기록 작성과 공개는 별개의 선택이다.
- 로그인 전 기록은 이 기기에만 저장되며 공개 여부는 사용자가 나중에 직접 선택한다.
- 계정·게스트 간 초안 소유 범위가 섞이지 않아야 한다.
- 감정과 해석·질문 태그는 구분해 표시하고, 추천어와 짧은 사용자 입력을 함께 지원하되 그룹당 3개·12자·중복 제거 계약을 유지한다.
- `CLASSIFIED_SIGNAL`은 명시적 공개 전 제목·본문·메모·수치·태그·지도 텍스트·접근성 이름을 노출하지 않는다.

### 계정과 개인정보

- 내 정보는 현재 표시 이름과 로그인 방식을 먼저 설명한 뒤 이름·비밀번호 변경을 독립 작업으로 제공한다.
- OAuth-only 계정에는 비밀번호 변경 작업을 노출하지 않는다.
- 표시 이름은 auth metadata와 `profiles.nickname`을 동일 DB 트랜잭션에서 갱신하고 부분 성공 상태를 만들지 않는다.
- localhost 화면 검토 모드는 실제 계정·세션·개인 기록을 만들거나 표시하지 않는다.
- Google OAuth는 Google Cloud client·Supabase provider·Production/Preview redirect allow list·신규 profile 생성 회귀가 함께 검증된 뒤 별도 승인으로 활성화한다.

### 모바일

- 모바일을 별도 축소 제품으로 만들지 않는다.
- 데스크톱과 같은 IA·데이터 계약·행동 흐름을 유지한다.
- Hero 통계는 모바일 첫 화면에서 숨긴다.
- 고정 제출 액션, 키보드, safe area, 하단 내비, 마지막 콘텐츠의 실제 geometry를 검증한다.

### 아카이브와 읽기 맥락

- 작품·미디어·기록·질문 아카이브는 HomeV2의 어두운 관측소 배경, 절제된 청록·황색 accent, 얇은 경계와 조용한 surface 계약을 공유한다.
- 전체 아카이브는 Home의 레이아웃을 복제하지 않고 검색·분류·비교에 필요한 정보 밀도를 보존한다.
- 읽기 모드는 누런 색 반전이 아니라 차가운 중성 배경과 명확한 본문·보조문·링크·경계·placeholder·focus 토큰을 사용한다.
- 읽기 모드의 본문과 입력 상태는 WCAG AA, 비텍스트 UI 경계와 focus 표시는 최소 3:1을 release gate에서 검증한다.
- 모바일 고정 모드 전환 버튼은 마지막 카드·행동과 겹치지 않도록 실제 최대 스크롤 geometry를 검증한다.

### Phase 2 — 발견 품질

목표: 작품·관측 정보·SF 개념을 실제 데이터로 연결한다.

- 작품 상세의 관련 SF 개념

- 같은 질문을 다룬 작품 연결

- 출처·마지막 갱신 시점
- 탐사 영역의 검색·필터 IA 통합

편집 추천 운영 계약:

- `신작 / 공개예정 / 편집 추천`은 서로 다른 콘텐츠 유형으로 유지한다.
- 편집 추천은 정확히 3권, 국내 정식 한국어판 서지, 독립적인 복수 출처, 표지 alt·권리 상태를 갖춘 구조화 기사다.
- 작업 흐름은 `선정 승인 → DRAFT 저장 → 편집 검수 APPROVED → 사용자 최종 발행`으로 분리하며, 일반 저장 경로는 `PUBLISHED`를 만들 수 없다.
- 스킬은 조사·역할 배정·승인 게이트만 지휘하고, 앱과 Supabase RPC가 저장·검증·공개 투영을 소유한다.
- 공개 상세 RPC는 `PUBLISHED`만 반환하고 selection approval·내부 메모·이미지 권리 검수 메모는 공개 payload에서 제거한다.
- 표지는 공식 출판사 또는 허용된 API의 HTTPS 원격 자산을 우선하며, 검증되지 않은 이미지를 로컬에 복제하지 않는다.

Admin 운영·자동화 계약:

- Admin 홈은 현재 운영하는 `신작 정보 관리`와 접속 보안만 노출하며, 게임화 수동 조작·회원 메모·빈 통계·커뮤니티 inline 관리는 기본 화면에서 제거한다.
- Admin 진입은 Supabase `app_metadata.role/roles=admin` 확인과 별도의 서버측 접속 비밀번호 세션을 모두 요구한다. 접속 비밀번호는 client bundle·브라우저 저장소·migration에 평문으로 저장하지 않는다.
- 비밀번호 hash와 session version은 관리자 전용 저장소에 보관하고, 변경 시 현재 비밀번호를 재검증한 뒤 기존 세션을 무효화한다.
- 신작 조사·국내판 서지·출판 일정 자동화는 `sf_discoveries`에 `NEW_RELEASE` 또는 `UPCOMING`의 `DRAFT`만 새로 생성한다. `PUBLISHED`, `published_at`, 승인 상태는 자동화가 설정할 수 없다.
- 자동화는 기존 DRAFT·게시물의 사용자 편집을 덮어쓰거나 기존 게시물을 병합하지 않는다. ISBN13, 외부 상품 ID, 원문 URL, 제목+출간일 순으로 중복을 차단하고 처음 본 항목만 추가한다.
- 자동화·스킬·커넥터는 비공개 초안 조사와 provenance 보강까지만 담당한다. Admin과 사용자가 수정·검수·표지 권리 확인·발행을 소유하며 자동 발행은 허용하지 않는다.
- 자동 입력 경계는 제목·유형·출시일·저자 표기·출판사·ISBN13·출처 URL·대표 이미지 provenance와 조회 시각을 보존하고, 확정되지 않은 필드와 표지 권리는 검토 필요 상태로 둔다.
- Aladin 키는 server-only `ALADIN_TTB_KEY`만 허용한다. `VITE_*`, URL, client bundle, migration, fixture, 로그에는 credential을 저장하지 않는다.

## 7. 측정할 제품 퍼널

초기에는 임의의 성장 목표보다 실제 기준선을 먼저 수집한다.

### 발견

- Home → 탐사 클릭
- 작품 목록 → 상세 진입
- 오늘의 발견 → 관련 작품 진입

### 기록

- 기록 시작
- 초안 저장
- 기록 완성
- 로그인 전 초안 복구
- 중도 이탈 지점

### 공개

- 공개 선택률
- 비공개 유지율
- 분류 신호 선택률
- 공개 후 Network 진입률

- Network 방문
- 공개 신호 상세 열람
- 신호 → 작품 이동
- 작품 → 다른 공개 신호 이동

- 소스별 실패율과 응답 시간

- 모바일 오버플로·고정 UI 회귀

## 8. 역할별 책임

- **보라**: 제품 우선순위, 범위 통제, 최종 검수, 출시 판정
- **윤경**: 보안·개인정보·공개 범위·데이터 무결성
- **현정**: 제품 위계·접근성·모바일·시각 품질
- **리아**: 구현·테스트 계약·회귀·릴리스 자동화
- **선영**: SF 한국어 용어·안내 문구·관측 정보 편집 문체

## 9. 변경 관리 규칙

기능 또는 IA를 변경할 때 다음 순서로 관리한다.

1. 사용자 상태와 제품 문제를 먼저 정의한다.
2. 정상·빈 상태·오류·부분 장애·공개 범위를 명세한다.
3. 테스트 계약을 먼저 추가하거나 함께 갱신한다.
4. 데스크톱과 모바일을 같은 반응형 구조로 검증한다.
5. Preview를 실제 사용자 여정과 긴 스크롤까지 검증한다.
6. 윤경·현정·리아 독립 검토 후 보라가 후보를 판정한다.
7. 승인된 매니페스트와 동일한 후보만 commit·push·Production에 배포한다.
8. 출시 후 결과와 새 결정·P2를 이 문서에 반영한다.
